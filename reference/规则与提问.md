# 规则与提问

## 1. 任务描述 → 规则（脚本自动识别，规划摘要第一行显示）

| 用户说法（示例） | 规则 |
|---|---|
| 仅需提取中间电压 / 只取 Vnorm / 只要标称电压 | 条件后缀只取 `_Vnorm` |
| 只取最小电压 / 仅 Vmin（最大同理） | 只取 `_Vmin`（`_Vmax`） |
| 全部电压 / 所有条件 | 所有条件合并 |
| 将数值范围填入 / 写法为“XX~XX” / 最小~最大 | 多值取范围，分隔符按原话（~、～、至） |
| 多个数值取最大值（最小值、平均值） | 多值取最大（最小、平均） |
| A 列的标题为测试项 | 标签列 = A（默认自动识别） |
| 第一行的数字表示样品号 | 样品号所在行 = 1（默认自动识别） |
| 保留 3 位小数 | 小数位 = 3 |
| 规范名后的“（备案+第2次变更）” | 版本号，写入“验证依据”字段 |

没识别到的规则会变成问题（如“取哪种条件”“多值怎么填”），不会默认瞎填。

## 2. 测试数据表的约定（可自动识别）

- 首行（或前几行中）是样品号：1、2、3 / 1#、#1 / 样品1 / S1 / No.1。
- 标签列（通常 A 列）是测试项；**标签为空的行属于上一个测试项**（同一项多个数值）。
- 同一标签出现多次 = 多段数据；条件后缀 `_Vnorm/_Vmin/_Vmax` 用于筛选。
- 标签拆词规则：`VOD_VOS_DOTVOD_DOTVOC_DIFF_AC` → 参数名 VOD、VOS、ΔVOD、ΔVOS（DOT=Δ），其余为限定词（DIFF、AC、IN0、vicmLow、150mV、0V075 …）。
- 复合标签有 N 个参数名且有 N 段数据 → 按出现顺序一一对应（会出“标签对应”确认题）。
- 标签多出无法识别的词且与另一标签参数相同（如 `TR_TF_N_VOHL` 对 `TR_TF_N`）→ 视为其他测量项，忽略。
- 记录中没有的测试项（如 OS、FLUSH1）→ 忽略并列入审核报告。
- 规范表注为“设计保证，不测试”的参数 → 实测值留空并在批注说明。
- PASSED/PASS/OK → “合格”；任何 FAILED → “不合格”（并计入不合格）。
- 数字格式：保留 2 位小数，但至少 3 位有效数字，去掉末尾 0（107.347968→107.35，-0.888689→-0.889，40.0→40）。
- 合理性检查：实测值与规范限值比较；超限 → 批注⚠；量级/符号明显不符（0/1 标志、正负相反）→ 出“数值合理性”题。
- 符号别名在 `rules/aliases.json`（如 VTL→VTH-、VOC→VOS），可按产品追加；`answer --remember` 记住的对应关系在 `rules/learned.json`。

## 3. 问题类型（questions.md 中的 [类别]）

| 类别 | 何时出现 | 常见选项 |
|---|---|---|
| 测试条件 | 数据有多种条件后缀且任务描述没说取哪种 | 仅Vnorm / 仅Vmin / 仅Vmax / 全部 |
| 多值取值 | 同一样品多值且没说怎么填 | 范围 / 最大 / 最小 / 平均 |
| 数据对应 | 标签无法确定对应哪个参数 | 各段→参数 的几种组合 / 不填 |
| 标签对应 | 复合标签按顺序拆分、近似匹配 | 正确 / 有误我来说明 |
| 数值合理性 | 实测值与限值量级或符号不符 | 照填原始数据（推荐，不用“合格”掩盖超限）/ 取负 / 填合格 / 留空；0/1 通过标志（如 DR）推荐“留空”，“填规范限值”只作备选（会把限值当实测值，慎选） |
| 字段取值 | 字段有多个候选值 | 各候选值 |
| 无来源字段 | 字段在源文件中找不到 | 留空待人工 / 我现在提供（字段=值；…） |
| 缺少源文件 | 批注要求的文件没提供 | 稍后提供（标待补充）/ 跳过 / 用其他文件代替 |
| 定位章节 | 找不到要求的源章节 | 检索到的候选 / 跳过 |
| 章节取舍 | 匹配到的源章节为空 | 是否纳入相邻章节（多选） |
| 呈现方式 | 源内容是“序号）名称：值”列表 | 转表格 / 保持列表 |
| 数据来源 | 提供了多个表格文件 | 选择哪个是测试数据 |
| 来源核对 | 数据文件的文件名和内容里没有型号/批号 | 已核对 / 暂未核对（推荐，定稿前必须核对，必须由用户本人回答） |
| 样品对应 | 数据文件的样品号与记录的样品号完全没有交集 | 不对应，实测值不填（推荐）/ 按顺序对应（批注和审核报告会标明“数据4号→记录1#”） |
| 未读取内容 | 源文件有扫描页或读取失败的页 | 不能当作“源文件没有这项值”，由用户决定如何补读 |

## 4. 提问要点

- 一次最多 4 题；先问影响面大的（测试条件、多值取值、缺少源文件）。
- 按 `questions.md` 原样展示题目、序号及推荐项。`questions --ask-json` 会把推荐项排在前面；记录回答时，取选项描述里的原序号。如果表单截短了候选项，展示 `questions.md` 的完整选项供选择。
- 用户的回答是文字（不是选项）时：`DI answer <任务目录> Qn="原话"`。
  “无来源字段”题的文字格式：`字段=值；字段=值`，脚本会自动填入。
  其他题的文字回答，脚本会提示你据此用 `set`/`add-section` 手工处理。
- 用户说“都按推荐”：`DI draft <任务目录> --defaults`。推荐项只在这一版草稿里生效、批注标“⚠待确认”，不会保存为回答；`final` 会拦截，直到用户正式回答这些问题。用户的正式回答与草稿采用的默认不同时，要重新出草稿再定稿。
- “来源核对”“样品对应”两类题必须由用户本人回答，不得替用户选“已核对”或“按顺序对应”。
