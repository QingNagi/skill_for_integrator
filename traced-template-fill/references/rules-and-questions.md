# 规则与提问

## 1. 任务描述 → 规则（脚本自动识别，规划摘要第一行显示）

| 用户说法（示例） | 规则 |
|---|---|
| 仅需提取中间电压 / 只取 Vnorm / 只要标称电压 | 条件后缀只取 `_Vnorm` |
| 只取最小电压 / 仅 Vmin（最大同理） | 只取 `_Vmin`（`_Vmax`） |
| 全部电压 / 所有条件 | 所有条件合并 |
| 将数值范围填入 / 写法为“XX~XX” / 最小~最大 | 多值取范围，分隔符按原话（~、～、至） |
| 多个数值取最大值（最小值、平均值） | 多值取最大（最小、平均） |
| A 列的标题为测试项 | 标签列 = A（默认自动识别） |
| 第一行的数字表示样品号 | 样品号所在行 = 1（默认自动识别） |
| 保留 3 位小数 | 小数位 = 3 |
| 规范名后的“（备案+第2次变更）” | 版本号，写入“验证依据”字段 |

任务描述未明确测试条件或汇总方式时，查看对应问题并记录用户选择。

## 2. 测试数据表的约定

默认标签规则适用于接口芯片测试记录。其他产品线可在 `new` 或 `run` 加 `--test-rules 产品规则.json`。文件可只写要覆盖的字段，建立任务时会把覆盖值存进 `job.json`。批量建立时可传 `batch new 清单.csv --test-rules 产品规则.json`，或单独填写各行的 `测试规则` 列。安装包中的默认标签配置见 `rules/test-data.json`。

```json
{
  "cond_pattern": "@(cold|hot)$",
  "preferred_conditions": ["cold"],
  "cond_keep": ["cold"],
  "no_suffix": "ask",
  "token_separator": "/",
  "delta_prefixes": ["DELTA"],
  "qualifier_pattern": "^(IN|OUT)[0-9]+$",
  "split_compound": false,
  "decimals": 3,
  "min_sig": 3,
  "precision": "source",
  "symbol_formats": {"R": {"decimals": "limit", "precision": "fixed"}}
}
```

`cond_pattern` 用一个捕获组提取条件，空字符串关闭后缀识别。`token_separator` 是不带捕获组的分隔正则。`split_compound` 控制是否提供复合标签的分段顺序候选。分段填写均需明确确认，设为 false 时可在回答中逐段输入参数符号。`precision` 支持 `source`（保留来源中明确写出的末尾零）、`trim`（去尾零）和 `fixed`（按设定小数位及有效位补零）。简单 Excel 数值格式如 `0.0000` 可提供显示精度；复杂会计、条件格式或仪器本身的精度需另行核对。

`symbol_formats` 可按记录中的参数符号覆盖 `decimals`、`min_sig` 和 `precision`。上例的 R 使用上下限中较多的小数位数；例如上限 1.3560 对应 4 位小数。若两端均无可识别数值，`"limit"` 使用 2 位小数。最少有效位及跨限值时保留原精度的规则仍生效。

- 首行（或前几行中）是样品号：1、2、3 / 1#、#1 / 样品1 / S1 / No.1。
- 标签列通常为 A 列。标签为空、样品列有读数的行属于上一项。若某只样品在同组读数中缺行，其结果留空，审核报告列出待复核的原始范围。
- 条件后缀 `_Vnorm/_Vmin/_Vmax` 用于筛选。选定特定条件时，`no_suffix: "ask"` 将未标条件的项留空并提问。已确认该批无后缀项均适用时可用 `keep`，仅保留显式命中项时可用 `drop`。
- 数值的源单位缺失时需核对。明确的源单位与记录要求不一致时留空，等待补充换算依据或手工录入。电源后缀只说明电压类别；记录还要求负载、电流等试验条件时，也需要来源佐证。
- 标签拆词规则：`VOD_VOS_DOTVOD_DOTVOC_DIFF_AC` → 参数名 VOD、VOS、ΔVOD、ΔVOS（DOT=Δ），其余为限定词（DIFF、AC、IN0、vicmLow、150mV、0V075 …）。
- 复合标签、别名及近似符号列为候选。用户核对每段的行号和参数后再填写。多个通道或测试标签落在同一参数上时，需选择采用哪一组或确认一起汇总。
- 标签多出无法识别的词且与另一标签参数相同（如 `TR_TF_N_VOHL` 对 `TR_TF_N`）→ 视为其他测量项，忽略。
- 记录中没有的测试项（如 OS、FLUSH1）→ 忽略并列入审核报告。
- 规范表注为“设计保证，不测试”的参数 → 实测值留空并在批注说明。
- 纯状态序列按来源结论登记，全部通过填“合格”，出现失败填“不合格”。数值与状态混合时，该只样品该项留空并保留引用。
- 默认按 2 位小数、至少 3 位有效数字修约。普通值如 107.347968 写作 107.35，带明确精度的 1.2300 保留为 1.2300。按未修约值核对上下限。若修约改变合格判断，写入足够区分限值的原精度，例如上限 1.35、实测 1.3504 时保留 1.3504。原始最小值和最大值不同时，如果修约会让它们显示为同一个数，保留能区分的原始端点。多值取均值、最小值或最大值时，样品判定仍检查全部原始读数。
- 合理性检查：实测值与规范限值比较；超限 → 批注⚠；量级/符号明显不符（0/1 标志、正负相反）→ 出“数值合理性”题。
- 符号别名在 `rules/aliases.json`（如 VTL→VTH-、VOC→VOS），可按产品追加；`answer --remember` 经用户原话确认的对应关系写入本项目的 `.doc-integrator/learned.json`；旧安装的 `rules/learned.json` 可以迁入此处。

## 3. 问题类型（questions.md 中的 [类别]）

| 类别 | 何时出现 | 常见选项 |
|---|---|---|
| 测试条件 | 数据有多种条件后缀且任务描述没说取哪种 | 仅Vnorm / 仅Vmin / 仅Vmax / 全部 |
| 多值取值 | 同一样品多值且没说怎么填 | 范围 / 最大 / 最小 / 平均 |
| 数据对应 | 标签无法确定对应哪个参数 | 各段→参数 的几种组合 / 不填 |
| 未注明条件 | 已选定电压条件，但部分测试项没有条件后缀 | 省略这些项目 / 已核对，可纳入 |
| 跨标签汇总 | 一个参数命中多个来源标签 | 留空 / 确认汇总 / 只取指定标签 |
| 测量单位、测试工况核对 | 源表未证实记录所要求的单位、负载或其他工况 | 留空 / 已对照原始记录核实 |
| 数值合理性 | 原始值的符号或量级可疑 | 留空 / 已核实原值，记录超限。极性可疑时可确认反号；疑似 0/1 标志时可指定通过码，每只样品按实际状态给出结论。规范限值不作为实测值。 |
| 字段取值 | 字段有多个候选值 | 各候选值 |
| 无来源字段 | 字段在源文件中找不到 | 留空待人工 / 我现在提供（字段=值；…） |
| 缺少源文件 | 批注要求的文件没提供 | 稍后提供（标待补充）/ 跳过 / 用其他文件代替 |
| 定位章节 | 找不到要求的源章节 | 检索到的候选 / 跳过 |
| 章节取舍 | 匹配到的源章节为空，邻近章节有正文、表格或插图 | 选择是否纳入有内容的章节。候选全空时直接登记待补充 |
| 呈现方式 | 源内容是“序号）名称：值”列表 | 转表格 / 保持列表 |
| 数据来源 | 提供了多个表格文件 | 选择哪个是测试数据 |
| 来源核对 | 数据文件的文件名和内容里没有型号/批号 | 已核对 / 暂未核对（推荐，定稿前必须核对，必须由用户本人回答） |
| 样品对应 | 来源与目标的样品号集合不同 | 仅采用相同编号；若两边均唯一且数量相同，可按用户确认的逐列对照处理。重复编号的列留空。 |
| 规范表选择 | 同一区域有多张得分接近的候选规范表 | 选择来源表或跳过该区；采用同一选择核对目标里已有的规范值 |
| 测试数据工作表 | 一个数据文件包含多张候选工作表 | 选择工作表 / 留空 |
| 未读取内容 | 源文件有扫描页或读取失败的页 | 不能当作“源文件没有这项值”，由用户决定如何补读 |

## 4. 提问要点

- 一次最多 4 题；先问影响面大的（测试条件、多值取值、缺少源文件）。
- 按 `questions.md` 原样展示题目、序号及推荐项。`questions --ask-json` 会把推荐项排在前面；记录回答时，取选项描述里的原序号。如果表单截短了候选项，展示 `questions.md` 的完整选项供选择。
- 用户的回答是文字（不是选项）时：`DI answer <任务目录> Qn="原话"`。
  “无来源字段”题的文字格式：`字段=值；字段=值`，脚本会自动填入。
  “数据对应”题可按来源段顺序输入逗号分隔的参数符号。其余需要手工录入的项目可用 `set` 或 `add-section`。
- 用户说“都按推荐”：`DI draft <任务目录> --defaults --user-quote "都按推荐"`。推荐项只在这一版草稿里生效、批注标“⚠待确认”，不会保存为回答；`final` 会拦截，直到用户正式回答这些问题。用户的正式回答与草稿采用的默认不同时，要重新出草稿再定稿。
- “来源核对”“样品对应”两类题必须由用户本人回答，不得替用户选“已核对”或“按顺序对应”。
