# 示例（照着做即可）

以下示例中，`DI` 表示离线包的 `& "<技能目录>/run.ps1"`。使用源码时可替换为 `python "<技能目录>/scripts/di.py"`。

---

## 示例 1：规范电特性 + 测试数据 → 验证记录

模拟任务（文件名、型号和数值均为示例）：
> 请将 DEMO-100 详细规范（备案+第 2 次变更）中的电特性填写进验证记录的对应位置。
> 再从 B.xlsx 提取中间电压条件（_Vnorm）的结果。第一行是样品编号，A 列是测试项。每个样品有多次测量时填写“最小值~最大值”。跳过模板中没有对应位置的测试项。

### 1. 找文件
```
DI find DEMO-100 详细规范
DI find 验证记录
DI find B.xlsx
```
“验证记录”匹配到 `样例验证记录.doc` 和 `样例验证记录_成品示例.doc`：成品示例不是目标，用前者（不确定时问用户）。

### 2. 建任务并规划
```
DI run -t "样例验证记录.doc" -s "DEMO-100详细规范.docx" -s "B.xlsx" --task "<用户原话整段>"
```
规划摘要（节选）：
```
从任务描述识别的规则：条件=仅Vnorm；多值=范围；范围写法=XX~XX；标签列=A；样品号行=1；规范版本=“备案+第2次变更”
[规范表→记录] S1:T3 表 1 电特性（36行） → T0.D1 第15-50行；列：测试参数←特性+符号、测试条件←条件…、极值/最小…
[测试数据] S2 B.xlsx：样品1#、2#、3#；条件=Vnorm；多值=范围(最小~最大)；已对应 32 个参数；忽略 4 项
忽略的数据项：FLUSH1、OS（记录中无对应参数）；TR_TF_N_VOHL、TR_TF_P_VOHL（视为其他测量项）
```

### 3. 待确认问题（脚本给出，必须问用户）
| 题 | 内容 | 推荐 |
|---|---|---|
| 数据对应 | `TRJ_TDJ_JT1` 两段数据分别对应哪个参数 | 先留空，核对仪器导出说明中的段序 |
| 数据对应 | 复合标签的每一段分别代表哪个参数 | 从原始记录确认段序，未确认时留空 |
| 未注明条件 | 已选中间电压，无条件后缀的行是否同样适用 | 暂时省略，核对工况记录 |
| 数值合理性 | VTH- 原始值为正，记录的限值为 -150~0 mV | 先留空，核对电压极性与单位 |
| 数值合理性 | DR 原始数据只有 0/1，记录的下限为 800 Mbps | 先留空。获得速率测量或状态码定义后，再据实填写数值或结论 |
| 字段取值 | 产品名称规格型号填“DEMO-100”还是“DEMO-100型演示器件” | 前者 |
| 无来源字段 | 主要测试仪器、封装说明书编号、样品批号、裸片LOGO、温湿度、试验起止时间 | 留空待人工 |

收到用户实际回答后，用本次任务中的题号和选项序号记录。例如，若用户给第一个问题选择第二项，运行 `DI answer "<任务目录>" Q1=2`。再次查看待答问题。

### 4. 草稿
`DI draft <任务目录>` → `草稿/样例验证记录_草稿_v1.docx`，效果：
- 第15–50行逐行复制规范表1（含续表）：`TTL输入高电平电压V_IH | V_DD=3.15V | 2 | V_DD | V`（保留上下标；纵向合并的条件逐行填写；表注 a 的项不填实测值）。
- 表头“测试条件”后补上规范表头说明“(除另有规定外，-55℃≤T_A≤125℃，V_DD=3.15~3.45V)”。
- 实测值：`合格`（全部 PASSED）、`101.20~102.40`（来源明确保留两位小数，RIN 样品1，4个值取范围）、`41.25`（ICC 单值）。默认保留来源中明确写出的末尾零，临界值按未修约值核对上下限。
- “验证依据标准条款”=规范标题+版本；各数据区都有完整依据时可按样品汇总合格数；仍缺必测项目时，数量留待核对。
- 每行两条批注：【规范】…▶打开原文（跳到规范快照中该行，黄色高亮）；【实测】…▶1# ▶2# ▶3#（打开 B.xlsx 快照并选中对应单元格区域）。

### 5. 审核与定稿
用户审核后：`DI final <任务目录>` → `终稿/样例验证记录_终稿.docx` 和 `.doc`（模板是 .doc，所以同时出 .doc）。

## 示例 2：按批注要求从任务书摘抄（文档摘抄.docx）

目标 `文档摘抄.docx` 的每个标题上有批注，批注就是要求：
```
1、项目背景      ← “研制任务书中的第一部分”
2、性能指标      ← “研制任务书中的产品特征、电特性和产品定义书中的电特性”
3、质量和可靠性要求 ← “查看研制任务书可靠性章节”
4、进度要求      ← “查看研制任务书进度章节”
```
命令：
```
DI run -t "文档摘抄.docx" -s "任务书节选.docx" --task "编制文档摘抄.docx，目标产品DEMO-100"
```
规划摘要：
```
[章节摘抄] 1、项目背景 ← S1:H2“项目背景”          （“第一部分”按序号找到（1））
[章节摘抄] 2、性能指标 ← S1:H3“产品特征”；S1:T1.R3.C0.P5“电特性参数指标”；待补充(产品定义书)
[章节摘抄] 3、质量和可靠性要求 ← S1:H11“质量与可靠性要求”
[章节摘抄] 4、进度要求 ← S1:H14“进度要求”
```
待确认问题：
1. 缺少“产品定义书” → 稍后提供（先标“待补充”）/ 跳过 / 用已有文件中的相近内容代替
2. 源章节“质量与可靠性要求”内容为空 → 是否同时纳入相邻的“适用的法律法规要求”“潜在失效后果”（可多选）
3. “进度要求”是“1）节点：时间”列表 → 转为表格（加表号）/ 保持列表

草稿效果：多个来源时自动加“（1）（2）…”小标题；同一内容来自不同文件时注明出处，如“电特性参数指标（研制任务书）”“电特性（产品定义书）”；
列表转表格时自动生成“表1  进度计划表”；全部按默认排版规范；模板原有批注保留，每段摘抄另加【摘自】批注含▶打开原文链接。

拿到新的产品定义书后，重新建任务，在 `run` 命令中为新文件加一个 `-s`。已有任务的 `add-section` 只接受该任务里已登记的来源。

## 示例 3：用户只给了一句话

> “把规范里的封装尺寸表摘到报告第3章”

1. `DI find 规范`、`DI find 报告` 确定文件（多个候选就问）。
2. `DI run -t 报告.docx -s 规范.docx --task "把规范里的封装尺寸表摘到报告第3章"`
3. 若规划没有自动对应到第3章：`DI search <任务目录> 封装尺寸` 找到源ID（如 S1:H8），
   `DI add-section <任务目录> --to "3" --src S1:H8`，再 `DI draft <任务目录>`。
