## 定稿修复

旧版本在决定日志被清空后，仍可凭答案缓存把草稿定为终稿。1.2.0 会先核对关键决定的原话、问题、输入指纹和所选答案。新记录还绑定填写效果、规则和附件。来自 Word 的答复会核对草稿、评论和回复标识，跨任务复用会回查原任务的记忆授权。明确接受遗留项时，原始决定仍须可核对。旧版可匹配的记录继续可用。操作记录本身无法证明提供原话的人具有组织签署权。

## 部署及复现

- 技能 ZIP、精简依赖、三个架构运行时、三个本地完整套装共八件。Windows ZIP 的内外归档使用固定元数据。分别复建得到相同摘要，文件内容与对应的原始输入按清单核对。正式源码 ZIP 中的 62 个文件均为 UTF-8 文本。完整包仅供本地验收。
- Windows x64 正式配对首次部署并验证双语 OCR 用时 7.688 秒。移走部署载荷后再次运行用时 0.269 秒。用错误版本配对会停止，并保留之前的可用缓存。独立精简依赖通过离线 pip 哈希校验安装和 PDF 文本读写。
- Windows 通过本机 Word 2010 和隔离的 LibreOffice 26.8.3.1 验证 DOCX→DOC→DOCX、两条审核批注以及含 17.8 V 的单页 PDF。高级 Word 版本、WPS 和用户单位的策略组合仍需在对应环境验证。
- Linux x86_64 和 aarch64 的 QEMU 来宾均关闭网卡，以普通用户验证配对拒绝、首次双语 OCR、自带 Python、草稿和来源、热缓存、并发修复以及损坏载荷处理。来宾 glibc 2.36，未安装 LibreOffice，已验证缺失转换器时的提示。每种架构做 3 次冷启动和 5 次热启动。x86_64 草稿耗时中位数为 52.19/6.51 秒，aarch64 为 51.55/6.14 秒。QEMU 仿真计时与物理机不同。
