# 1.2.0 与 1.3.0 的未见来件对照

在相同配置的本机 Claude Code 2.1.316 和 DeepSeek 上，每个版本分别用六个新会话处理相同的六份来件。两版均正确填写 66 格、正确留空 66 格，两个库房摘录也都选对现行文件、摘对章节。1.3.0 的两组成对表格还保留了未受影响位置的显示精度。文件可按样品和章节回到对应的来源。[逐题数字、文件摘要与判分结果](generalization.json)

| 来件变化 | 交付检查 | 1.2.0 全程（秒 / 调用） | 1.3.0 全程（秒 / 调用） |
|---|---|---:|---:|
| 新样品编号、随机读数与列序 | 18 格有据、15 格留空，含临界值 | 390.49 / 75 | 197.05 / 50 |
| 新光电符号及本批别名 | 18 格有据、15 格留空，含纳安换算成微安 | 387.32 / 69 | 403.37 / 78 |
| 前述第一题的来源列反转，另放历史同名表 | 33 个数值或空白不变，全部选中本批。1.3.0 的显示文本也逐格相同 | 338.43 / 76 | 271.03 / 46 |
| 前述第二题撤去两条程序段序 | 恰好 6 格从有据变为留空，其他 27 格数值或空白保持。1.3.0 的其余显示文本亦保持 | 409.03 / 101 | 336.88 / 74 |
| 两份同名库房规程，按批注摘两章 | 两章逐字进入对应栏目，批注书签分别落在现行规程对应章节 | 258.93 / 57 | 346.35 / 84 |
| 现行库房规程缺一章，退役版仍有 | 只摘有据章节，另一栏留空，审核报告指出缺失。未摘入其他章节或旧版内容 | 224.08 / 38 | 320.80 / 67 |

**数值相同也可能丢失书写精度。** 在 1.2.0 的第一组成对题中，三处从 1.85、1.63、1.88 变为 1.850、1.630、1.880。第二组成对题撤去段序后，有三处不相干的读数同时变了末尾零。基础数值评分接受两种写法，逐格文本对照能检出这六处变化。以 1.2.0 作候选反向运行新检查，返回质量未通过；以 1.3.0 作候选正向复验通过。两组最终稿显示一致性在新版本均得到验证。

**逐项复查的出处。** 先核对每次任务的原始来件 SHA-256 和实际选用的文件路径，再读取交付 Word 的批注、超链接及快照。每版 66 个实填数值逐一核到源工作表、样品列、原读数，以及换算后的值。同名表场景核对了本批与历史批的实际内容。每版三个实摘段落逐一核对来源书签与段落原文。缺章题还检查了报告中是否点名缺项。这些检查在模型退出后进行。

**过程仍有多余动作。** 普通会话在两个库房任务中都访问了退役版；交付件只引用现行版。1.3.0 的完整摘录任务还尝试额外转换 PDF，缺章任务重复出到 v5，并尝试给审核报告另加缺件说明。模型对批注里的书名和章节名分别作了处理，第一个任务的草稿一次出成，前期查阅仍花了时间。若优化这类任务，验收应检查“已授权的来源 + 指定章节”是否一次匹配，以及缺章理由能否从计划直接进入交付报告。同时保留同名来源未指定版本时的澄清、缺证留空及逐项来源核对。需要限制模型读取范围的部署，可由宿主只开放本次获准的资料目录。

**复测范围。** 新旧包均按原归档摘要核对，来件和答案在启动模型前封存，同一评分器复读实际交付件。四份表格来自两组基础数据，另两份为同一库房任务的有章与缺章版本，每题每版一次，耗时包含模型与宿主波动。合成题的生成随机种子没有保存，原始来件、原始答案及其摘要已保留，可逐字节重跑。既有 30 个验收会话独立统计。单位新模板、不同结构的工作表和其他领域的真实卷宗，仍需由独立审核人提供封存对照；这些样本的通过率可以单独积累。[原定全流程验收](README.md) · [复验命令与退出码](../../README.md#性能修改的泛化复验)
