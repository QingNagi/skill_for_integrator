# 溯源填写助手 1.3.0 综合验收

本轮使用独立项目中的模拟来件，调用本机 Claude Code 和配置的 DeepSeek，再从交付的 DOCX 读取结果与项目外的封存答案逐格比较。重复运行统计保留首次失败、漏填、错填和出稿后的工具调用。每个离线包的 SHA-256 与对应测试一起登记。

## 候选一暴露的问题

五模板的五次结果均为 200/200，但最后一份草稿后的工具调用分别为 24、15、31、12 和 44 次。在 163 格验证记录上，五次中有两次未经复核即出稿，其中一次错填 3 格、漏填 18 格；另一次生成三个版本，最后一版错填 12 格、漏填 6 格。模型把一般填写委托当成不同型号和本批原始数据的核对意见，其中一次还通过手工操作填写缺少程序段序依据的格子。[两组合成变体的独立核对](variants.md)

第二候选采用批量清单一次交付全批结果，受保护的积极确认须有适用原话或证据。复演首次失败会话时，原来的型号、批次和条件确认被退回。未获清单支持的 18 个手工推测值也被拦截。正式离线验证和实际模型多次评测分别记录，最终以同一份冻结包作为验收对象。
