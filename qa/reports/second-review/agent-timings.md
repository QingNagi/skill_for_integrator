## 交付复核

- **同名来源。** 两组都先列出甲、乙两份任务书，选定后均摘对乙组正文并生成 Markdown 审核报告。有技能的草稿含链接，目标快照的“项目背景”书签可解析。无技能的结果在项目根目录，含正确的正文来源说明，保留的原模板批注中没有来源链接；早期自动计数仅搜索子目录，复核时已补查根目录。
- **缺件后补件。** 第一轮两组都列出缺失的 `任务书.docx` 并暂停，均未生成填好的草稿。第二轮补件后，两组都从“项目背景”逐字摘入指定句，形成草稿和报告。有技能的批注指向快照中的“项目背景”书签；无技能的原生批注链接能打开任务书文件，链接没有章节锚点。
- **按草稿批注修改。** 在可用的 v1 正文旁预置一条审核批注，要求保留已有背景、追加“标识复核”原文并补来源链接。两组均保留 v1 和原始输入的文件哈希，v2 含原背景、新增的指定原句及两个正确的快照章节书签，均有 Markdown 报告。有技能的被测版本在报告摘要登记新增章节，但在逐项来源表漏列该行。已按此样例修复，并用同一任务重新规划，得到 `S1:H0`、`S1:H1` 各一行；表中保留当时实测时间。[追加与替换回归](../../../tests/test_manual_targets.py)
- **任务内定位章节。** 模板索要“堆放次序”，给定的任务书仅有“项目背景”和“标识复核”。第一轮两组都询问如何处理，未生成草稿。有技能组展示程序返回的正式 Q1，两组收到同一句“跳过，这一节暂时留空”。检查两份成品的 Word 正文，均只填了项目背景，“堆放次序”标题下为空。技能组登记了 Q1 和选择原话，批注可定位章节书签。对照组的来源批注链接可打开任务书。

## 计量口径

每个组使用独立工作目录和会话，第二轮恢复第一轮会话。缺件、批注修改和任务内定位章节按顺序串行执行，来源和模板均为测试程序生成。对照组禁用技能指令，两组开放同样的本地文件读写、搜索和 Python 调用，禁用 MCP 和 hooks。技能组额外允许本项目的技能，并收到其源码入口。各组的工具计数来自模型输出的 tool_use 事件，含遭权限拒绝的调用。四类任务的拒绝次数按有／无技能分别为 0／7、1／6、0／8 和 0／7。token 数分别来自 Claude 的 input_tokens、cache_read_input_tokens 和 output_tokens，所有组的 cache_creation_input_tokens 均为 0。

缺件、批注修改和正式待答题使用源码 ZIP `traced-template-fill-review-source.zip`，SHA-256 为 `f9118cc4f950a55a00f932bee9a2a6865f2710d72399739d132d05eb924b7abc`。同名选择采用本轮较早的开发副本，SKILL.md 的 SHA-256 为 `1900ac712c307bb956c24871cbb8626bf7bafb572123587b4d54268d7ba0bcaf`。这些数据来自同一宿主和模型，未计真人往返等待。表中四类任务的模型计时仅对应本段列出的被测副本。
