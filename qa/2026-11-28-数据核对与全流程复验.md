# 溯源填写助手的数据核对与全流程复验

2026 年 11 月 28 日，本次验收使用源码提交 `a84e462dce2d0bf347391e4d36f0f6d701000432`。内网包在本机构建，仓库公开源码、测试和构建方法。独立验收的 Windows 完整包与两个 Linux 本地交付包的识别依据见下表。

## 取值正确性

| 核对项目 | 实际结果 |
|---|---|
| 历史真实验证记录 | 按模板行、参数和样品编号对齐 96 格。13 格文字相同，5 格数值等价，78 格不同。逐格重读当前工作簿能复算这 78 格的旧计划值。缺少证明旧成品与当前工作簿同批的记录，也缺少部分仪器单位、工况、分段和状态码说明。最终包产生 16 个核对问题，计划有 36 行规范和 1 个依据字段；96 个实测位置留待核实。 |
| 真实章节摘抄 | 复查原列为“不同”的五段。四段涉及源内容占位、正文为空或缺少文件；另一段忠实保留了来源措辞。进度表的四个日期另计，保留来源精度。最终计划有 6 条章节登记，含待补提示；只保留缺件、呈现方式 2 个问题。两份真实来件的 SHA-256 前后一致，任务均停在人工确认前。 |
| 带独立答案的新盲测 | 先写定 12 个目标格的答案，再比较两个版本生成的 Word。旧版 9/12，新版 12/12，含 5 格正确填写和 7 格正确留空。5 个实测来源区间与独立答案一致。原生 Word 中的 6 个 Excel 链接都能打开对应快照，包含一个待核项的链接。仅对虚构来件模拟有依据的审核答复。 |
| 回归样例 | 电特性范围 8/8，章节草稿 4 条批注、2 条来源链接。审核员批注和手动修改在终稿保留。未复核 OCR 的终稿受到拦截。同名来件分别列出路径，等待使用者选定。 |

规划器按样品号对齐数据列，把状态、混合数据、未标条件和单位不明的记录分开处理。一个型号带额外后缀时需单独核对。数张规范表匹配度相近时可选择或跳过。报告保留暂缓格的原因及可回读的原始范围。

## 平台与离线安装

| 环境 | 实际经过的步骤 |
|---|---|
| Windows x64，隔离用户环境的 PATH 中无系统 Python | 从实际交付 ZIP 展开，首次自动安装内置 Python、OCR、模型及依赖，首次自检成功。随后复用同版环境。两条 `run.cmd` 同时首次运行，使用相同缓存，仅一条触发首次自检。 |
| Microsoft Word 2010 与隔离的 LibreOffice 26.8.3.1 | 两套后端各自生成、审核、定稿，实际转换 DOCX→DOC→DOCX，核对正文、原生批注和导出 PDF 的数值、制作程序。另将 Windows TEMP/TMP 指向一个普通文件，用旧 DOC 模板从入口生成草稿，读回规定正文、4 条批注和 2 条来源链接。 |
| 本地 Debian 12，x86_64、aarch64 | 两台 QEMU 虚拟机分别使用对应交付包。禁用网络、普通用户、只读来件，验证冷安装、缓存复用、损坏修复和中文路径。两个来宾均退出 0。来宾未安装办公转换程序。 |
| 原生 Linux CI | 两种 CPU 分别在无网络的验收步骤中运行，均用真实 LibreOffice 完成转换。CI 在原生机器重构测试包，交付包由上述虚拟机另验。[两架构运行记录](https://github.com/QingNagi/skill_for_integrator/actions/runs/46066178337) |
| 本地 Claude Code | 只将虚构来件用于模型验收。完整任务生成 1 份正确草稿；另一次同名来源任务列出两条路径，未生成草稿。实际模型工具调用为 5 次和 3 次，其中完整任务有一次 Bash 调用被宿主权限规则拒绝，随后通过允许的入口完成。 |

带坐标的 PDF 文字、OCR 及 457 个表格单元格与上版在 12 页上的回读对照一致，逐格检查了位置、合并跨度和文本。扫描标题有一个零置信错字，现并列显示正确的 PDF 元数据标题与原始识别，标出低置信字词。独立单行识别支持元数据标题。扫描页原始的数字和来源坐标均得到保留。

## 完整任务耗时

在同一台 Windows 电脑上使用同一份来件，交替执行上版与本版的实际离线入口。下表为已安装场景，每版各 5 次取中位数。检查了草稿或终稿内容、来源链接、审核报告及应保留的空格。耗时不包含人工等待和模型推理。

| 用户任务 | 上版 | 本版 |
|---|---:|---:|
| 章节摘录，交付可审核草稿、来源快照和报告 | 0.662 秒 | 0.601 秒 |
| 章节摘录、查看审核差异、确认模板批注保留并生成终稿 | 1.534 秒 | 1.387 秒 |
| 扫描工单，规划遇缺件暂停，再回读 PDF 原页核实指定字段 | 1.950 秒 | 0.774 秒 |

全新应用缓存、首次部署并交付章节草稿，单次分别为 8.253 秒和 7.519 秒。PDF 缓存命中时直接读取先前解析的数据，实际加载离线原生代码时仍验证 wheel 和解包文件。批量答案按任务一次重算，源文件或选项变化后要求重新确认；输入在草稿后替换也会在定稿前检出。

清理了重复的规范表评分、旧的覆盖逻辑、源文件重复登记、空转的表格遍历和 TXT 的二次逐行拼接。型号与依据字段共享取值和引用逻辑，批量与单项答复共享选项校验。空章节周围也没有正文、表格或插图时，直接登记待补，省去一次没有可用材料的提问。
